# 🚀 Руководство по генерации лекций

Этот документ описывает полный процесс создания лекций из `description.md` до готовых модулей в `Courses/`.

---

## 📋 Обзор процесса

```
Courses/{Lang}_{Level}/description.md
        ↓
    Анализ структуры курса
        ↓
    Создание папок в Courses/{Lang}_{Level}/
        ↓
    Для каждого модуля:
    ├── Генерация lecture.md
    └── Генерация quiz.md
        ↓
    Проверка по LECTURE_CHECKLIST.md
        ↓
    Review и публикация
```

---

## 📁 Структура входных данных

### Файл description.md

Располагается в `Courses/{Lang}_{Level}/description.md`

**Формат:**
Файл `description.md` содержит:
- Описание курса (целевая аудитория, уровень сложности, что изучат)
- Цели курса
- Требования (prerequisites для всего курса)
- Структуру курса с описанием модулей

**Пример структуры:**
```markdown
# Курс: Грамматика [языка] (уровень [уровень])

## Описание курса
[Описание курса. Целевая аудитория, уровень сложности, что изучат.]

## Цели курса
[Что студент сможет после прохождения курса]

## Требования
[Prerequisites для всего курса]

## Структура курса
### Лекция 1. [Название модуля]
[Описание содержимого модуля]
...
```

## 🔧 Пошаговый процесс

### Шаг 1: Анализ description.md

1. Открыть `Courses/{Lang}_{Level}/description.md`
2. Определить:
   - Название курса
   - Целевую аудиторию
   - Количество модулей
   - Prerequisites для курса

### Шаг 2: Создание структуры папок

```bash
# Создать папку курса
mkdir -p Courses/[CourseName]

# Создать папки модулей
mkdir -p Courses/[CourseName]/01_ModuleName
mkdir -p Courses/[CourseName]/02_ModuleName
# ... для каждого модуля
```

### Шаг 3: Генерация lecture.md

Для каждого модуля:

1. Скопировать `LECTURE_TEMPLATE.md` → `lecture.md`
2. Заполнить содержимое согласно:
   - Описанию модуля из `description.md`
   - Стандартам из `LECTURE_STANDARD.md`
   - Примеру из `LECTURE_EXAMPLE.md`

### Шаг 4: Генерация quiz.md

Для каждого модуля:

1. Скопировать `QUIZ_TEMPLATE.md` → `quiz.md`
2. Создать **полный квиз** с 20-40 вопросами, покрывающими:
   - Learning Objectives из лекции
   - Ключевые концепции
   - Практические сценарии
3. **Обязательно включить:**
   - Все вопросы с вариантами ответов (A, B, C, D)
   - **Answer Key** (ключ ответов) с правильными ответами и пояснениями
   - **Scoring Guide** (шкала оценки) для интерпретации результатов
4. Квиз должен быть **полностью готовым** для использования студентами

**⚠️ ВАЖНО:** Квиз без Answer Key и Scoring Guide считается неполным и не будет засчитан при проверке качества!

### Шаг 5: Проверка качества

1. Запустить скрипт проверки: `python3 course_validate_tools/analyze_quality.py Courses/{CourseName}`
2. Скрипт автоматически проверяет:
   - Длину лекций (600-1000 строк)
   - Наличие всех обязательных секций
   - **Полноту квизов:**
     - Наличие quiz.md файла
     - Количество вопросов (20-40)
     - Наличие Answer Key
     - Наличие Scoring Guide
   - Количество секций, блоков кода, Learning Objectives и Key Takeaways
3. **Важно:** Модуль без полного квиза (20+ вопросов, Answer Key, Scoring Guide) не может получить оценку "Отлично"
4. Проверить каждый модуль по `LECTURE_CHECKLIST.md`
5. Убедиться, что балл ≥ 125/155
6. Исправить найденные проблемы

## 🤖 Промпт для AI-генерации

При использовании AI (Claude, GPT и др.) для генерации контента, используйте следующий промпт:

### Промпт для генерации лекции

```
Создай лекцию для модуля курса согласно стандартам CourseBuilder.

## Входные данные

**Курс:** [Название курса]
**Модуль:** [XX_ModuleName]
**Описание модуля:** [описание из description.md]
**Prerequisites курса:** [requirements из description.md]

## Требования к лекции

1. **Структура** (обязательные секции):
   - H1: Название модуля
   - H2: Конкретная тема
   - 📋 Prerequisites (2-4 пункта)
   - 🎯 Learning Objectives (3-5 целей с глаголами действия)
   - 5-12 основных секций с нумерацией (## 1., ## 2., ...)
   - Подсекции (### 1.1, ### 1.2, ...)
   - 💡 Key Takeaways (3-5 пунктов)
   - 🚀 Next Steps

2. **Метрики:**
   - Длина: 600-1000 строк
   - Примеров предложений/правил: 20-40 примеров
   - Время чтения: 30-45 минут

3. **Стиль:**
   - Дружелюбный, но профессиональный тон
   - От простого к сложному
   - Каждый пример с переводом и объяснением
   - Объяснять не только "как", но и "зачем" (когда использовать правило)

4. **Примеры:**
   - Реальные предложения на изучаемом языке
   - Переводы и транскрипции где необходимо
   - Примеры правильного и неправильного использования
   - Таблицы с формами и исключениями

5. **Эмодзи** (только для секций):
   📋 Prerequisites, 🎯 Objectives, 💡 Takeaways, 🚀 Next Steps, ⚠️ Warnings, ✅/❌ Good/Bad

Сгенерируй полную лекцию в формате Markdown.
```

### Промпт для генерации quiz.md

```
Создай quiz.md для модуля курса согласно стандартам CourseBuilder.

## Входные данные

**Модуль:** [XX_ModuleName]
**Learning Objectives из лекции:**
1. [Objective 1]
2. [Objective 2]
...

**Ключевые темы лекции:**
- [Тема 1]
- [Тема 2]
...

## Требования к quiz

**⚠️ КРИТИЧЕСКИ ВАЖНО:** Квиз должен быть **полностью составлен** согласно `QUIZ_TEMPLATE.md`. Неполные квизы (без вопросов, без Answer Key, без Scoring Guide) не будут засчитаны при проверке качества!

1. **Количество:** 20-40 вопросов (рекомендуется 25-30)

2. **Распределение:**
   - 40% — понимание грамматических правил
   - 40% — практическое применение (выбор правильной формы, построение предложений)
   - 20% — исключения и частые ошибки

3. **Типы вопросов (особенно для A1-A2):**
   - **Вопросы с пропусками**: предложение с пропущенным словом, выбор из 4 вариантов
     ```
     He _____ to school every day.
     A) go  B) goes  C) going  D) went
     ```
   - **Вопросы на порядок слов**: слова в неправильном порядке, выбор правильной последовательности
     ```
     Слова: 1) I  2) coffee  3) drink  4) every  5) morning
     A) 1-3-2-4-5  B) 1-2-3-4-5  C) 3-1-2-4-5  D) 1-3-4-2-5
     ```
   - **Обычные вопросы на выбор**: выбор правильной формы, правила, использования

4. **Формат каждого вопроса:**
   - Номер и тема: ## Question N: [Тема]
   - ⚠️ **ВАЖНО:** В заголовках вопросов НЕ добавляйте комментарии типа "Тип: ...". Заголовок должен быть простым: `## Question N: [Тема вопроса]` без дополнительных описаний типа "Тип: Выбор правильной формы", "Тип: Заполнение пропуска" и т.д.
   - Текст вопроса (может включать предложения на изучаемом языке)
   - 4 варианта ответа (A, B, C, D)
   - Только один правильный ответ
   - Неправильные ответы должны быть правдоподобными
   - Правильный ответ не должен выделяться длиной и детализацией
   - Неправильные ответы не должны быть узкими настолько чтобы было очевидно, что они неверные
   - Слово "только" часто выдает неправильный ответ. Не надо этим злоупотреблять.

5. **Answer Key (ОБЯЗАТЕЛЬНО):**
   - Раздел "## Answer Key" с правильными ответами для всех вопросов
   - Формат: `N. X) [Правильный ответ]` или таблица
   - Пояснение должно объяснять ПОЧЕМУ это правильно (опционально, но рекомендуется)

6. **Scoring Guide (ОБЯЗАТЕЛЬНО):**
   - Раздел "## Scoring Guide" или "## Шкала оценки"
   - Рекомендуемые диапазоны:
     - 90-100% (18-20 из 20): Отлично
     - 70-89% (14-17 из 20): Хорошо
     - 50-69% (10-13 из 20): Удовлетворительно
     - <50% (<10 из 20): Нужно повторить материал

**Сгенерируй полный quiz.md с вопросами, Answer Key и Scoring Guide!**
```

### Перед началом
- [ ] Изучен `description.md` целевого курса

- [ ] Определены prerequisites курса
- [ ] Создана структура папок

### Для каждого модуля
- [ ] `lecture.md` создан из шаблона
- [ ] Все обязательные секции заполнены
- [ ] 3-5 Learning Objectives с глаголами действия
- [ ] 3-5 Key Takeaways
- [ ] 20-40 примеров предложений с переводами и объяснениями
- [ ] Длина 600-1000 строк
- [ ] `quiz.md` создан (20-40 вопросов)
- [ ] Все вопросы имеют варианты ответов (A, B, C, D)
- [ ] **Answer Key присутствует** с правильными ответами
- [ ] **Scoring Guide присутствует** для интерпретации результатов
- [ ] Вопросы покрывают Learning Objectives
- [ ] Проверка по LECTURE_CHECKLIST.md пройдена (≥125 баллов)

### Финализация курса
- [ ] Все модули прошли проверку
- [ ] Prerequisites между модулями согласованы
- [ ] Next Steps ссылаются на существующие модули
- [ ] Нет broken links
- [ ] Терминология единообразна

## 🎯 Критерии качества готового модуля

### Must Have (обязательно)
- ✅ Все обязательные секции присутствуют
- ✅ Все примеры предложений корректны и имеют переводы
- ✅ Learning Objectives измеримы (глаголы действия)
- ✅ **Quiz.md полностью составлен:**
  - 20-40 вопросов с вариантами ответов (A, B, C, D)
  - **Answer Key** с правильными ответами
  - **Scoring Guide** для интерпретации результатов
- ⚠️ **ВАЖНО:** 
  - Модуль без полного квиза (20+ вопросов, Answer Key, Scoring Guide) не может получить оценку "Отлично" при проверке качества!
  - Модуль без квиза или с неполным квизом (нет Answer Key, меньше 15 вопросов) получит оценку "Требует улучшений"
- ✅ Quiz покрывает материал лекции
- ✅ Балл по чеклисту ≥ 125/155

### Should Have (желательно)
- ✅ Прогрессия от простого к сложному
- ✅ Практические примеры из реального мира
- ✅ Объяснение "зачем", а не только "как"
- ✅ Warning блоки для частых ошибок

### Nice to Have (бонус)
- ✅ Pro Tips для продвинутых пользователей
- ✅ Сравнительные таблицы
- ✅ Визуальные схемы (если применимо)

## 📊 Примеры

### Пример: От description.md к модулю

**Вход (description.md):**
```markdown
### Лекция 2. Present Simple
Настоящее простое время — образование, использование, маркеры времени.
```

**Выход (структура lecture.md):**
```markdown
# Present Simple
## Настоящее простое время в английском языке

---

## 📋 Prerequisites
- Базовое знание английского алфавита
- Понимание структуры простого предложения
- Знание личных местоимений (I, you, he, she, it, we, they)

## 🎯 Learning Objectives
- Образовывать утвердительные, отрицательные и вопросительные предложения в Present Simple
- Правильно использовать окончания -s/-es для третьего лица единственного числа
- Применять маркеры времени (always, usually, often, etc.)
- Различать случаи использования Present Simple и других времен

## 1. Что такое Present Simple
### 1.1 Основные случаи использования
...

## 2. Образование утвердительных предложений
### 2.1 Формы глагола
...

## 3. Отрицательные и вопросительные предложения
...

## 4. Маркеры времени
...

## 5. Исключения и особые случаи
...

## 6. Практические примеры
...

## 💡 Key Takeaways
- **Present Simple** используется для регулярных действий и фактов
- В третьем лице единственного числа добавляется -s/-es
- Вспомогательный глагол do/does используется в отрицаниях и вопросах
- Маркеры времени помогают определить правильное время

## 🚀 Next Steps
- [03_Present_Continuous](../03_Present_Continuous/) — настоящее длительное время
- [04_Past_Simple](../04_Past_Simple/) — прошедшее простое время
```
