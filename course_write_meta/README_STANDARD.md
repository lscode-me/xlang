# Стандарт написания README для курсов

## 📋 Общие требования

README.md является **главным входным документом курса** и должен предоставлять полную информацию о содержании, целях и структуре обучения.

### Минимальные требования к README:

- ✅ Файл **README.md** в корневой директории курса
- ✅ Минимальная длина: **200+ строк** (для детального описания)
- ✅ Все 20 модулей должны быть описаны с примерами
- ✅ Обязательные секции (см. ниже)
- ✅ Примеры для каждого модуля с переводом на русский
- ✅ Ссылки на все модули в формате `[Module Name](folder_name/)`

---

## 📐 Структура README

README должен содержать следующие обязательные секции в указанном порядке:

### 1. Заголовок курса (H1)

```markdown
# Название курса на русском языке
```

**Пример:**
```markdown
# Грамматика английского языка A1
```

---

### 2. Описание курса (## Описание курса)

**Требования:**
- Минимум 3-4 абзаца
- Объяснить, для кого предназначен курс
- Указать уровень (A1, A2, B1 и т.д.)
- Описать охват материала (какие темы покрываются)
- Указать формат обучения

**Пример:**
```markdown
## Описание курса

Данный курс предназначен для начинающих изучать английский язык с нуля или с минимальной базой.  
Курс охватывает **ключевые грамматические темы уровня A1**, необходимые для повседневного общения: знакомство, семья, еда, покупки, время, место, желания и простые действия.

Каждая лекция посвящена **одной грамматической теме**, содержит объяснение правил и типичные примеры с лексикой уровня A1.
```

---

### 3. Цели курса (## Цели курса)

**Требования:**
- Минимум 5-7 целей
- Начинать с глагола действия (сможет...)
- Конкретные и измеримые результаты
- Использовать маркированный список (-)

**Пример:**
```markdown
## Цели курса

После прохождения курса студент сможет:

- строить простые утвердительные, отрицательные и вопросительные предложения;
- использовать настоящее, прошедшее и будущее время в базовых формах;
- использовать артикли и основные предлоги;
- задавать простые вопросы и отвечать на них;
- описывать людей, места и вещи простыми словами;
- говорить о себе, семье, привычках и планах.
```

---

### 4. Требования (## Требования)

**Требования:**
- Указать предварительные знания (если есть)
- Указать технические требования (если есть)
- Если курс для начинающих - указать минимальные требования

**Пример:**
```markdown
## Требования

Перед началом курса рекомендуется:

- Иметь желание изучать английский язык
- Знать латинский алфавит
- Понимать базовые понятия грамматики родного языка
```

---

### 5. Структура курса (## Структура курса)

**Требования (КРИТИЧЕСКИ ВАЖНО):**
- Все 20 модулей должны быть описаны
- Для каждого модуля обязательно:
  - H3 заголовок с номером, названием и ссылкой: `### [01. Module Name](01_Folder_Name/)`
  - Маркированный список основных тем (3-6 пунктов)
  - Подзаголовок **Примеры:** (жирный текст)
  - Минимум 2-4 примера с переводом (если применимо)
  - Разделитель `---` после каждого модуля

**Формат для каждого модуля:**

```markdown
### [01. Название модуля](01_Folder_Name/)

- Основная тема 1
- Основная тема 2
- Основная тема 3
- Основная тема 4

**Примеры:**

- Пример 1 (Example 1)
- Пример 2 (Example 2)
- Пример 3 (Example 3)

---
```

**Реальный пример:**

```markdown
### [02. Личные местоимения и глагол to be (быть)](02_Personal_Pronouns_and_To_Be/)

- Личные местоимения: I, you, he, she, it, we, they
- Формы глагола to be: am, is, are
- Утвердительные, отрицательные и вопросительные предложения
- Краткие ответы

**Примеры:**

- I am a student.
- She is a doctor.
- Are you happy? - Yes, I am.

---
```

### 6. Дополнительные секции (рекомендуемые)

Следующие секции рекомендуются для улучшения качества README:

#### 6.1. Методические рекомендации (## Методические рекомендации)

**Содержание:**
- Как организованы лекции
- Какие примеры используются
- Визуальные элементы (схемы, таблицы)
- Переводы и пояснения

**Пример:**
```markdown
## Методические рекомендации

- Каждая лекция содержит четкое объяснение грамматического правила
- Примеры используют простую лексику уровня A1
- Показаны все три формы: утвердительная, отрицательная и вопросительная
- Включены типичные ошибки русскоговорящих учащихся
- Все примеры имеют перевод на русский язык
- Визуальные схемы и таблицы для систематизации материала
```

#### 6.2. Особенности для целевой аудитории

Описать типичные трудности для конкретной языковой группы студентов.

**Пример:**
```markdown
## Особенности для русскоговорящих студентов

При изучении курса учитываются типичные трудности:

- Артикли (их отсутствие в русском языке)
- Порядок слов в вопросах
- Использование вспомогательных глаголов
- Различие между Present Simple и Present Continuous
```

#### 6.3. Формат обучения (## Формат обучения)

**Пример:**
```markdown
## Формат обучения

Каждый модуль включает:

1. **Лекцию (lecture.md)** с подробным объяснением грамматики и множеством примеров
2. **Тест (quiz.md)** с 20 вопросами для проверки усвоения материала

После прохождения всех 20 модулей студент будет готов перейти к изучению английского языка на уровне A2.
```

## ✅ Чек-лист качества README

Перед публикацией проверьте:

- [ ] README.md существует в корне курса
- [ ] Длина минимум 200 строк
- [ ] Есть заголовок H1 с названием курса
- [ ] Есть секция "Описание курса" (3+ абзаца)
- [ ] Есть секция "Цели курса" (5+ целей со списком)
- [ ] Есть секция "Требования"
- [ ] Есть секция "Структура курса"
- [ ] Все 20 модулей описаны в "Структуре курса"
- [ ] Каждый модуль имеет:
  - [ ] H3 заголовок со ссылкой на папку
  - [ ] Список основных тем (3-6 пунктов)
  - [ ] Подзаголовок "**Примеры:**"
  - [ ] Минимум 2 примера
  - [ ] Разделитель `---`
- [ ] Ссылки на модули работают и указывают на правильные папки
- [ ] Все примеры имеют переводы (где применимо)
- [ ] Используются правильные заголовки (H2 для основных секций, H3 для модулей)
- [ ] Нет опечаток и грамматических ошибок

## ❌ Типичные ошибки

### 1. Слишком короткий README
```markdown
# Course A1

This is a grammar course.

## Modules
1. Module 1
2. Module 2
...
```

**Проблема:** Нет детального описания, целей, примеров.

### 2. Нет примеров для модулей
```markdown
### [01. Articles](01_Articles/)

Learn about articles.

---
```

**Проблема:** Нет списка тем и примеров.

### 3. Неправильные ссылки
```markdown
### [01. Articles](Articles/)  <!-- ❌ Неправильно -->
### [01. Articles](01_Articles/)  <!-- ✅ Правильно -->
```

### 4. Нет разделителей между модулями
```markdown
### [01. Module 1](01_Module_1/)
...

### [02. Module 2](02_Module_2/)  <!-- ❌ Нет --- между модулями -->
```

### 5. Использование нумерованного списка вместо маркированного для тем модуля
```markdown
1. Topic 1  <!-- ❌ Неправильно -->
2. Topic 2

- Topic 1   <!-- ✅ Правильно -->
- Topic 2
```

## 📊 Метрики качества README

Автоматическая проверка README в `analyze_quality.py` проверяет:

| Метрика | Норма | Критично |
|---------|-------|----------|
| Длина файла | 200+ строк | < 100 строк |
| Модулей описано | 20 | < 15 |
| Модулей с примерами | 20 | < 15 |
| Обязательных секций | 4 (Описание, Цели, Требования, Структура) | < 3 |
| Работающих ссылок | 20/20 | < 15/20 |
