# Примеры использования валидатора курсов

## Проверка всех курсов

```bash
python3 course_validate_tools/analyze_quality.py Courses/
```

Выводит отчет по всем курсам в папке Courses/, включая:
- README метрики для каждого курса
- Метрики лекций и квизов для каждого модуля
- Общую статистику по всем курсам

---

## Проверка одного курса

```bash
python3 course_validate_tools/analyze_quality.py Courses/English_A1/
```

Выводит детальный отчет по курсу English_A1:
- README: статус, строки, секции, модули с примерами
- Сводка по курсу: средняя длина лекций, блоки кода, квизы
- Структура: наличие обязательных секций
- Качество: процент отличных/хороших/проблемных модулей
- Детали по каждому модулю: строки, секции, код, LO, KT, quiz

---

## Что проверяет валидатор

### README.md (новое!)

✅ **Наличие файла**: README.md в корне курса

✅ **Обязательные секции**:
- Заголовок H1
- Описание курса (## Описание курса)
- Цели курса (## Цели курса) - минимум 3 цели
- Требования (## Требования)
- Структура курса (## Структура курса)

✅ **Качество структуры**:
- Все 20 модулей имеют ссылки (### [01. Name](folder/))
- Все 20 модулей имеют описание тем (список с -)
- Минимум 15/20 модулей имеют примеры (**Примеры:**)

✅ **Метрики**:
- Минимум 200 строк (рекомендуется для детального описания)
- Минимум 5 целей курса

**Пример хорошего README**: [Courses/English_A1/README.md](../Courses/English_A1/README.md)

**Стандарт**: [README_STANDARD.md](README_STANDARD.md)

---

### Лекции (lecture.md)

✅ **Структура**:
- Prerequisites
- Learning Objectives (3-5)
- Key Takeaways (3-5)
- Next Steps

✅ **Метрики**:
- Длина: 600-1000 строк
- Основных секций (H2): 5-12
- Блоков кода: 15-30

✅ **Качество примеров**:
- Каждый пример с переводом
- Минимум 20 примеров предложений

---

### Квизы (quiz.md)

✅ **Обязательные компоненты**:
- 20-40 вопросов (## Question N)
- Answer Key в табличном формате
- Scoring Guide (## Scoring Guide)

✅ **Формат Answer Key** (критично для shuffle_quiz_answers.py):

```markdown
## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Explanation text |
| 2 | A | Explanation text |
```

❌ **Неправильный формат**:
```markdown
1. B) Explanation  <!-- Не работает с shuffle! -->
```

## Интерпретация результатов

### README статус

| Статус | Описание |
|--------|----------|
| ✅ Отлично | 200+ строк, все секции, все модули описаны с примерами |
| ✅ Хорошо | Есть недочеты, но основная структура присутствует |
| ⚠️ Требует улучшений | Отсутствуют некоторые секции или мало модулей описано |
| ❌ Серьёзные проблемы | Менее 100 строк, отсутствуют критичные секции |
| ❌ README отсутствует | Файл README.md не найден |

### Модуль качество

| Статус | Описание |
|--------|----------|
| ✅ Отлично | Все метрики в норме, полный квиз с правильным форматом |
| ✅ Хорошо | Небольшие отклонения (короткая лекция или мало примеров) |
| ⚠️ Требует улучшений | Несколько проблем (короткая лекция, мало кода, проблемы с квизом) |
| ❌ Серьёзные проблемы | Критические проблемы (очень короткая лекция, нет квиза, неправильный формат Answer Key) |

## Типичные проблемы и решения

### Проблема: README ⚠️ Требует улучшений

**Причина**: Не все модули описаны или отсутствуют примеры

**Решение**: Используйте [README_STANDARD.md](README_STANDARD.md) как шаблон:
1. Добавьте описание для каждого модуля
2. Добавьте **Примеры:** для каждого модуля (минимум 2 примера)
3. Используйте разделитель `---` между модулями

---

### Проблема: ❌ Модулей с правильным форматом Answer Key: 0/20

**Причина**: Answer Key не в табличном формате

**Решение**: 
1. См. [QUIZ_TEMPLATE.md](QUIZ_TEMPLATE.md)
2. Используйте скрипт для конвертации (если есть старый формат):

```python
# Пример конвертации в таблицу
old_format = """
1. B) Because...
2. A) It means...
"""

new_format = """
| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Because... |
| 2 | A | It means... |
"""
```

---

### Проблема: ⚠️ Короткая лекция (< 600 строк)

**Причина**: Недостаточно примеров и объяснений

**Решение**: Добавьте дополнительные секции:
- Больше примеров с переводом
- Типичные ошибки студентов
- Дополнительные упражнения
- Культурные заметки (для языковых курсов)
- Сравнение с другими языками

См. [LECTURE_STANDARD.md](LECTURE_STANDARD.md) секция "Рекомендуемые дополнительные секции"

---

### Проблема: ⚠️ Мало блоков кода (< 15)

**Причина**: Примеры не обернуты в блоки кода

**Решение**: Оборачивайте все примеры в код-блоки:

```markdown
```
I am a student.
Я студент.
\```
```

Каждый пример предложения должен быть в отдельном блоке кода.

## Автоматическое исправление

### Конвертация Answer Key в таблицу

```bash
# Создайте скрипт fix_answer_keys.py и запустите:
python3 fix_answer_keys.py Courses/English_A1/
```

### Изменение заголовка Scoring

```bash
# Если у вас "## Scoring" вместо "## Scoring Guide":
find Courses/English_A1/ -name "quiz.md" -exec sed -i '' 's/^## Scoring$/## Scoring Guide/g' {} \;
```

---

## Continuous Validation

Рекомендуется проверять качество курса после каждого изменения:

```bash
# После редактирования модуля:
python3 course_validate_tools/analyze_quality.py Courses/English_A1/

# Проверить только один модуль (косвенно через весь курс):
python3 course_validate_tools/analyze_quality.py Courses/English_A1/ | grep "01_Module_Name"

# Сравнить до/после изменений:
python3 course_validate_tools/analyze_quality.py Courses/English_A1/ > before.txt
# ... внести изменения ...
python3 course_validate_tools/analyze_quality.py Courses/English_A1/ > after.txt
diff before.txt after.txt
```

## Итоговый чек-лист перед публикацией курса

- [ ] README.md: ✅ Отлично (200+ строк, все модули описаны)
- [ ] Все модули: ✅ Отлично или ✅ Хорошо (нет ⚠️ или ❌)
- [ ] Все квизы: 20+ вопросов, Answer Key (табличный формат), Scoring Guide
- [ ] Средняя длина лекции: 600-1000 строк
- [ ] Все обязательные секции присутствуют (Prerequisites, LO, KT, Next Steps)
- [ ] Нет критических ошибок в отчете валидатора

Если все пункты выполнены - курс готов к публикации! 🎉
