# Стандарт лекций CourseBuilder

## 📋 Назначение документа

Этот документ определяет единые требования к структуре, содержанию и оформлению всех лекций во всех курсах CourseBuilder.

**Цель:** обеспечить согласованность, качество и удобство обучения независимо от тематики курса.

**Применяется к:** всем языковым курсам в `Courses/` (English_A1, Türkçe_A1, и др.)

---

## 🎯 Общие принципы

### 1. Философия курса
- **Практичность**: Теория подкреплена реальными примерами предложений
- **Ясность**: Сложные грамматические правила объясняем простым языком
- **Прогрессия**: От базового к продвинутому уровню
- **Релевантность**: Актуальные грамматические правила и современное использование языка
- **Применимость**: Навыки для реального общения и письма

### 2. Тон и стиль
- **Дружелюбный, но профессиональный**
- Обращение на "ты" / "вы" (выбрать одно и использовать везде)
- Избегать излишней формальности
- Мотивировать, но не развлекать
- Баланс между теорией и практикой

### 3. Целевая аудитория
- Студенты с базовыми знаниями изучаемого языка
- Изучающие язык, желающие углубить грамматические навыки
- Те, кто ценит понимание "почему так, а не иначе"

**Примечание:** Конкретная аудитория уточняется в `description.md` каждого курса.

## 📐 Структура лекции

### Обязательные секции (в указанном порядке)

```markdown
# [Название модуля]
## [Подзаголовок: что конкретно изучаем]

---

## 📋 Prerequisites
Что нужно знать перед началом

## 🎯 Learning Objectives
Что вы изучите в этом модуле

## 📁 Sample Data
Ссылка на данные для практики (если применимо)

---

## 1. [Основная секция 1]
### 1.1 [Подсекция]
### 1.2 [Подсекция]

## 2. [Основная секция 2]
...

---

## 💡 Key Takeaways
Главные выводы (3-5 пунктов)

## 🚀 Next Steps
Что изучить дальше, связанные темы

## 📚 Additional Resources
Дополнительные материалы (опционально)

---
```

### Требования к секциям

#### Header (первые 3 строки)
```markdown
# [Название]
## [Конкретная тема]

---
```

- H1: Название модуля (напр. "Object-Oriented Programming")
- H2: Конкретизация (напр. "Classes, Inheritance, Polymorphism")
- Разделитель `---`

#### Prerequisites
```markdown
## 📋 Prerequisites

Перед началом этого модуля вы должны:
- Знать базовую грамматику [предыдущая тема]
- Понимать структуру простого предложения
- [Опционально] Иметь базовый словарный запас по теме
```

**Правила:**
- 2-4 пункта
- Конкретные, проверяемые требования
- Ссылки на предыдущие модули, если применимо

#### Learning Objectives
```markdown
## 🎯 Learning Objectives

После завершения этого модуля вы сможете:
- [Глагол действия] + [конкретный навык]
- [Глагол действия] + [конкретный навык]
- [Глагол действия] + [конкретный навык]
```

**Правила:**
- 3-5 целей
- Использовать активные глаголы: создавать, применять, анализировать, разрабатывать
- Измеримые результаты обучения
- НЕ использовать: понимать, знать (слишком абстрактно)

**Примеры хороших objectives:**
- ✅ "Образовывать правильные формы глаголов в Present Simple"
- ✅ "Применять артикли a, an, the в различных контекстах"
- ✅ "Строить вопросительные предложения с правильным порядком слов"
- ✅ "Различать случаи использования разных времен"
- ❌ "Понимать грамматику" (плохо - неизмеримо)
- ❌ "Знать времена" (плохо - неконкретно)

#### Sample Data (для модулей с практикой)
```markdown
## 📁 Sample Data

**[Название набора примеров](../data/DataSamples.md)** — описание материалов для практики

Материалы для этого модуля:
- `data/examples.txt` — примеры предложений для анализа
- `data/exercises.md` — упражнения для закрепления
```

#### Key Takeaways
```markdown
## 💡 Key Takeaways

- **Ключевая концепция 1**: Краткое объяснение почему важно
- **Ключевая концепция 2**: Краткое объяснение почему важно
- **Ключевая концепция 3**: Краткое объяснение почему важно
```

**Правила:**
- 3-5 пунктов
- Формат: **Концепция**: объяснение
- Это должны быть самые важные идеи модуля
- То, что останется в памяти через месяц

#### Next Steps
```markdown
## 🚀 Next Steps

**Related Modules:**
- [Module X](../XX_Module/) — как связано
- [Module Y](../YY_Module/) — как связано

**Practice Ideas:**
- Задача для самостоятельной практики
- Проект для применения знаний

**Going Deeper:**
- Дополнительная тема для углубления
- Продвинутая концепция
```

## 📝 Требования к содержанию

### 1. Основные секции (H2)

**Нумерация:**
```markdown
## 1. Название секции
## 2. Название секции
## 3. Название секции
```

**Правила:**
- Нумеруются арабскими цифрами
- 5-12 основных секций на лекцию
- Логическая последовательность: от простого к сложному
- Каждая секция = законченная мысль

### 2. Подсекции (H3)

```markdown
### 1.1 Подсекция
### 1.2 Подсекция
```

**Правила:**
- Нумерация через точку: `1.1`, `1.2`, `2.1`, etc.
- 0-4 подсекций на основную секцию
- Если подсекций больше 4 — возможно, нужно разбить основную секцию

### 3. Структура секции

**Стандартная структура:**
```markdown
## N. [Название темы]

[1-2 абзаца введения: что это и зачем]

### N.1 [Подтема]

[Объяснение концепции]

**Пример:**
```[язык]
[код]
```

**Output:**
```
[результат выполнения]
```

[Объяснение что произошло]

### N.2 [Другая подтема]
...
```

### 4. Длина лекции

**Целевые метрики:**
- **Длина лекции:** 600-1000 строк
- **Время чтения:** 30-45 минут
- **Примеров предложений:** 20-40 примеров
- **Основных секций:** 5-12

**Если лекция слишком длинная (>1200 строк):**
- Разбить на два модуля
- Вынести продвинутые темы в отдельный модуль
- Убрать дублирование

**Если лекция слишком короткая (<400 строк):**
- Добавить больше примеров предложений
- Углубить объяснения правил
- Добавить исключения и частые ошибки
- Добавить практические сценарии использования

## 💻 Требования к примерам предложений

### 1. Формат примера

**Полный блок:**
```markdown
### Example: [Описательное название]

[1-2 предложения: что демонстрирует пример и зачем он нужен]

**Предложение:**
```
I go to school every day.
Я хожу в школу каждый день.
```

**Объяснение:**
В этом предложении используется Present Simple для выражения регулярного действия. Обратите внимание на [важная деталь].
```

### 2. Правила оформления примеров

**В примерах:**
- Предложения на изучаемом языке с переводом
- Транскрипция где необходимо (для произношения)
- Выбрать единый формат и использовать везде
- Объяснять неочевидные случаи, а не очевидные

**Плохо:**
```
I am student.  # Очевидно неправильно, но без объяснения почему
```

**Хорошо:**
```
I am a student.  # Артикль "a" обязателен перед исчисляемым существительным в единственном числе
Я студент.
```

### 3. Типы примеров

**Минимальный пример (концепция):**
```
# Демонстрирует только правило
I work.  # Без окончания -s для первого лица
Я работаю.
```

**Практический пример (применение):**
```
# Реальное использование в контексте
I usually go to the gym on Mondays.
Обычно я хожу в спортзал по понедельникам.
```

**Полный пример (с исключениями и нюансами):**
```
# Пример с исключением и объяснением
He goes to school.  # -es добавляется к глаголам, оканчивающимся на -o, -s, -x, -ch, -sh
Он ходит в школу.

She does her homework.  # Глагол do → does в третьем лице
Она делает домашнее задание.
```

**Правило:** Включать все три типа в пропорции 40% / 40% / 20%

### 4. Примеры должны быть:

- ✅ **Корректными**: Грамматически правильные предложения
- ✅ **Современными**: Актуальное использование языка (не устаревшие формы)
- ✅ **Естественными**: Соответствуют реальной речи носителей языка
- ✅ **Понятными**: Ясные и простые для понимания
- ✅ **Контекстными**: Показывают использование в реальных ситуациях

❌ **Избегать:**
- Устаревших или архаичных форм
- Слишком сложных конструкций без объяснения
- Примеров без контекста ("просто предложение")
- Неправильных или сомнительных форм

### 5. Показывать переводы и объяснения

**Всегда показывать перевод и объяснение:**

```markdown
**Пример:**
```
She works in a hospital.
Она работает в больнице.
```

**Объяснение:**
Глагол "work" в третьем лице единственного числа получает окончание -s. Артикль "a" используется перед исчисляемым существительным в единственном числе.
```

**Для сравнения правильного и неправильного:**
```
✅ Правильно: I have a book.
❌ Неправильно: I have book.
```

**Объяснение:** Артикль "a" обязателен перед исчисляемым существительным в единственном числе.

## 🎨 Стилистические требования

### 1. Эмодзи

**Использовать умеренно для:**
- Маркировки секций: 📋 📁 🎯 💡 🚀
- Важных замечаний: ⚠️ ✅ ❌ 💡
- Типов контента: 📚 💻 🔧

**Стандартные эмодзи:**
- 📋 Prerequisites
- 🎯 Learning Objectives / Goals
- 📁 Sample Data / Files
- 💡 Key Takeaways / Pro Tips
- 🚀 Next Steps / Advanced
- ⚠️ Warning / Caution
- ✅ Good practice / Correct
- ❌ Bad practice / Incorrect
- 📚 Theory / Concepts
- 💻 Practical / Code Examples
- 🔧 Tools / Commands
- 📊 Data / Results
- 🎓 Exercise / Practice

**НЕ использовать:**
- Много эмодзи подряд: ❌ 🚀🔥💯✨
- Эмодзи внутри предложений (только в началах секций)
- Случайные эмодзи без значения

### 2. Форматирование текста

**Жирный текст (`**text**`):**
- Ключевые термины при первом упоминании
- Важные концепции
- Заголовки в списках

**Курсив (`*text*`):**
- Акценты в предложениях
- Названия на английском в русском тексте
- Метапеременные (напр. *filename*, *pattern*)

**Код (`code`):**
- Грамматические термины и названия правил
- Отдельные слова и фразы на изучаемом языке
- Транскрипции
- Короткие фрагменты предложений (до 1 строки)

**Примеры:**

```markdown
**Правильно:**
Глагол `work` в третьем лице получает окончание -s.
Используйте **Present Simple** для выражения регулярных действий.

**Неправильно:**
Глагол work в третьем лице получает окончание -s.
Используйте Present Simple для выражения **регулярных действий**.
```

### 3. Списки

**Маркированные списки:**
```markdown
Используются для:
- Неупорядоченных элементов
- Преимуществ / недостатков
- Ключевых пунктов
```

**Нумерованные списки:**
```markdown
Используются для:
1. Последовательных шагов
2. Алгоритмов
3. Иерархических структур
```

**Вложенные списки (максимум 2 уровня):**
```markdown
- Level 1
  - Level 2
    - Avoid Level 3 (рефакторить)
```

### 4. Таблицы

**Использовать для:**
- Сравнения форм и правил
- Справочников по спряжению и склонению
- Таблиц с исключениями

**Формат:**
```markdown
| Column 1 | Column 2 | Column 3 |
|----------|----------|----------|
| Value    | Value    | Value    |
| Value    | Value    | Value    |
```

**Выравнивание:**
- Текст: по левому краю
- Числа: по правому краю
- Заголовки: по центру (опционально)

### 5. Цитаты и врезки

**Для важных замечаний:**
```markdown
> **💡 Pro Tip:**  
> Полезный совет или инсайт

> **⚠️ Warning:**  
> Важное предупреждение или частая ошибка

> **📝 Note:**  
> Дополнительная информация
```

### 6. Разделители

**Использовать `---` для:**
- Отделения header от контента
- Между крупными секциями (перед Key Takeaways, Next Steps)

**Не использовать:**
- Между каждой секцией (слишком много)
- Внутри секций

## ✍️ Языковые требования

### 1. Терминология

**Единообразие:**
- Выбрать ОДИН термин и использовать везде
- Создать глоссарий часто используемых терминов

**Примеры:**
- ✅ Используем: "функция" (не "метод" для standalone functions)
- ✅ Используем: "аргумент" (не "параметр" для вызова)
- ✅ Используем: "параметр" (для определения функции)

### 2. Перевод vs транслитерация

**Правило:** Использовать устоявшиеся переводы, НО оставлять английские термины в `code`

**Примеры:**
```markdown
✅ Хорошо:
Функция `map()` применяет трансформацию к каждому элементу.
Декоратор `@property` создает getter для атрибута.

❌ Плохо:
Функция map применяет трансформацию к каждому элементу. (без код-форматирования)
Декоратор эт-property создает геттер для атрибута. (транслитерация)
```

### 3. Длина предложений

**Целевые метрики:**
- Среднее: 15-20 слов
- Максимум: 30 слов
- Если длиннее — разбить на два

**Сложные предложения:**
- Разбивать на пункты списка
- Использовать короткие абзацы

### 4. Абзацы

**Правила:**
- 3-5 предложений на абзац
- Одна идея на абзац
- Пустая строка между абзацами

## 🔍 Требования к качеству

### 1. Технические требования

**Точность:**
- ✅ Технически корректная информация
- ✅ Работающие примеры кода
- ✅ Актуальные версии инструментов
- ❌ Устаревшие практики
- ❌ Неработающий код

**Проверяемость:**
```markdown
Плохо: "Этот код быстрее"
Хорошо: "Этот код в 2 раза быстрее (O(log n) vs O(n))"
```

### 2. Педагогические требования

**Прогрессия:**
- От простого к сложному
- От конкретного к абстрактному
- Новые концепции строятся на известных

**Примеры:**
```markdown
✅ Хорошая прогрессия:
1. Простое предложение: I work.
2. С наречием частоты: I usually work.
3. Сложное предложение: I usually work, but sometimes I study.

❌ Плохая прогрессия:
1. Сложное предложение (сразу сложное)
2. Простое предложение (проще после сложного)
```

**Объяснение:**
- Сначала ЧТО делает код
- Потом КАК он работает
- Наконец ПОЧЕМУ именно так

### 3. Полнота

**Каждое грамматическое правило должно включать:**
- Определение правила
- Зачем нужно (мотивация, когда используется)
- Как образовывать (формы, примеры)
- Когда использовать (контексты и сценарии)
- Частые ошибки и исключения

## 🎓 Примеры

### Пример хорошей секции

```markdown
## 3. Образование форм глаголов

В Present Simple глаголы изменяются в зависимости от лица и числа. Для большинства глаголов в третьем лице единственного числа добавляется окончание -s.

### 3.1 Базовое правило

**Формула:**
```
I/You/We/They + глагол (без изменений)
He/She/It + глагол + -s
```

**Пример: Глагол "work"**
```
I work.        Я работаю.
You work.      Ты работаешь.
We work.       Мы работаем.
They work.     Они работают.

He works.      Он работает.
She works.     Она работает.
It works.      Это работает.
```

Обратите внимание: окончание -s добавляется только в третьем лице единственного числа.

### 3.2 Исключения: окончание -es

Для глаголов, оканчивающихся на -o, -s, -x, -ch, -sh, добавляется -es:

```
go → goes      (идти)
do → does      (делать)
watch → watches (смотреть)
wash → washes  (мыть)
```

**Пример:**
```
She goes to school every day.
Она ходит в школу каждый день.

He watches TV in the evening.
Он смотрит телевизор вечером.
```

> **💡 Pro Tip:**  
> Используйте правило -es для глаголов, оканчивающихся на шипящие звуки. Это помогает произношению.

### 3.3 Частые ошибки

❌ **Неправильно:**
```
He work every day.  (отсутствует -s)
She go to school.   (отсутствует -es)
```

✅ **Правильно:**
```
He works every day.
She goes to school.
```

**Объяснение:** В третьем лице единственного числа окончание обязательно.
```

## 📝 Quiz файл (quiz.md)

К каждой лекции должен быть создан файл `quiz.md` с вопросами для проверки знаний.

### Структура quiz.md

```markdown
# [Module Name] - Quiz

[Краткое описание что проверяет квиз]

---

## Question 1: [Тема вопроса]

[Текст вопроса]

A) [Вариант ответа A]

B) [Вариант ответа B]

C) [Вариант ответа C]

D) [Вариант ответа D]

---

## Question 2: [Тема вопроса]
...

---

## Answer Key

1. [Буква] - [Правильный ответ] - [Краткое пояснение]
2. [Буква] - [Правильный ответ] - [Краткое пояснение]
...

---

## Scoring Guide

- **[90-100%]**: Отлично! Вы хорошо усвоили материал.
- **[70-89%]**: Хорошо. Повторите темы, в которых ошиблись.
- **[50-69%]**: Удовлетворительно. Рекомендуется повторить лекцию.
- **[Ниже 50%]**: Необходимо внимательно перечитать материал.

---
```

### Требования к quiz.md

**Количество вопросов:**
- Минимум: 20 вопросов
- Оптимум: 25-30 вопросов
- Максимум: 40 вопросов

**Типы вопросов:**

**Для уровней A1-A2 (рекомендуется):**
- **Вопросы с пропусками (fill-in-the-blank)**: предложение с пропущенным словом/формой
  ```markdown
  He _____ to school every day.
  A) go  B) goes  C) going  D) went
  ```
- **Вопросы на порядок слов**: слова даны в неправильном порядке
  ```markdown
  Выберите правильный порядок: 1) I  2) coffee  3) drink  4) every  5) morning
  A) 1-3-2-4-5  B) 1-2-3-4-5  C) 3-1-2-4-5  D) 1-3-4-2-5
  ```
- **Вопросы на выбор правильной формы**: выбор между вариантами использования

**Для всех уровней:**
- Вопросы на понимание грамматических правил (40%)
- Вопросы на практическое применение (40%)
- Вопросы на исключения и частые ошибки (20%)

**Правила составления вопросов:**
1. Каждый вопрос имеет **ровно 4 варианта ответа** (A, B, C, D)
2. Только **один правильный ответ** на вопрос
3. Неправильные ответы должны быть **правдоподобными** (не очевидно неверными)
4. Вопросы должны **покрывать Learning Objectives** из лекции
5. Не спрашивать о том, что **не было в лекции**
6. Вопросы должны быть **разного уровня сложности**

**Формат Answer Key:**
- Номер вопроса
- Буква правильного ответа
- Текст правильного ответа
- Краткое пояснение **почему это правильный ответ**

**Scoring Guide:**
- Разделить на 4 категории по процентам
- Дать рекомендации для каждой категории
- Мотивировать на изучение/повторение материала

### Пример вопроса

**Хороший вопрос (тип 1: заполнение пропуска):**
```markdown
## Question 5: Present Simple - третье лицо

Выберите правильную форму глагола для заполнения пропуска:

He _____ to school every day.
Он _____ в школу каждый день.

A) go

B) goes

C) going

D) went
```

**Ответ:** B - goes - В третьем лице единственного числа (he/she/it) глагол получает окончание -s или -es.

**Хороший вопрос (тип 2: порядок слов, для A1-A2):**
```markdown
## Question 6: Present Simple - порядок слов

Выберите правильный порядок слов в предложении:

Слова: 1) I  2) coffee  3) drink  4) every  5) morning

A) 1-3-2-4-5 (I drink coffee every morning)

B) 1-2-3-4-5 (I coffee drink every morning)

C) 3-1-2-4-5 (drink I coffee every morning)

D) 1-3-4-2-5 (I drink every coffee morning)
```

**Ответ:** A - 1-3-2-4-5 - Правильный порядок: подлежащее (I) + глагол (drink) + дополнение (coffee) + обстоятельство времени (every morning).

**Плохой вопрос:**
```markdown
## Question: English

What is English?

A) A language
B) A country
C) A food
D) A color
```
*Проблемы: слишком очевидно, не проверяет понимание грамматики, не связан с конкретной темой.*
